# 设备千问端到端

设备连接 `/v1/dialogue/ws`。默认 `HARDWARE_VOICE_ROUTE=realtime`，保留原级联实现；
可在服务器配置、连接的 `?route=cascade` 或每轮 `dialogue.start.route` 中切换。
优先级为 start 中的 route、连接查询参数、服务器配置。

## 默认配置

```ini
HARDWARE_VOICE_ROUTE=realtime
HARDWARE_QWEN_REALTIME_MODEL=qwen3.5-omni-flash-realtime
HARDWARE_QWEN_REALTIME_WS_URL=wss://dashscope.aliyuncs.com/api-ws/v1/realtime
HARDWARE_QWEN_REALTIME_VOICE=Tina
HARDWARE_QWEN_REALTIME_TRANSCRIPTION_MODEL=gummy-realtime-v1
HARDWARE_QWEN_REALTIME_ENABLE_SEARCH=true
HARDWARE_QWEN_REALTIME_TAIL_SILENCE_MS=200
```

`HARDWARE_QWEN_REALTIME_API_KEY` 可独立配置，未配置或留空时复用 `QWEN_API_KEY`。
模型、音色、转写和音频转码的默认值来自 `ASR_LLM_TTS_Server`；联网搜索按业务要求开启。
转写模型必须可用，因记忆和知识库检索依赖最终识别文本。上述模型、Tina、
gummy-realtime-v1 已在本机配置下通过真实上游握手及 session.update 确认。
若部署到另一百炼空间且上游不接受该模型，调整转写模型为该空间支持的值。
智能体音色字段继续保存，设备端到端目前统一使用 Tina。切换智能体仍切换人设、历史和知识库。
`QWEN_AUDIO_REALTIME_*` 小程序测试配置和页面不变。

## 设备协议

```json
{"type":"dialogue.start","device_sn":"你的设备SN","client_req":"本轮标识","route":"realtime","audio_format":"pcm","sample_rate":16000}
```

收到 `dialogue.ready` 后开始发送二进制录音帧，内容必须是 **16kHz / s16le / 单声道裸 PCM**。
实时采集时可不声明 `audio_bytes`；声明时必须与本轮实际上传总字节数相同。
设备采集结束（例如固件收到 PCM_FINISH）发送 `dialogue.commit` 或 `dialogue.end`，两者等价。
重复提交不生成第二次回答。Speex 只用于 `route=cascade`。

服务器收到录音帧立即转发，不缓存整段。收到结束事件后发送 200ms 尾静音并 commit，
等待千问最终转写，使用一次问题 Embedding 检索当前 user/agent 的摘要与关联知识库，
更新会话的 instructions 并等待确认，再发送 response.create。
参考资料不是新的用户消息，不保存到对话表。检索总等待默认 3 秒，异常不阻断普通回答。

千问返回的 24kHz PCM 经 FFmpeg 连续转换为 16kHz、64k MP3，使用同事的 CI 首帧兼容处理。
设备持续接收二进制 MP3。只有 response.done.status=completed、存在回答文字且 MP3 全部发完，
才将真实问答在同一事务写入 PostgreSQL、启动后台摘要，并发送 dialogue.done。
dialogue.done 表示服务器输出结束，不代表设备缓冲区播放完毕。

dialogue.cancel、断线、超限、转写/生成/转码错误都会清理该轮收发任务、上游和转码桥。
失败和取消不保存为成功问答。下轮 start 重新加载设备绑定和当前 Agent。

## 功能边界与验证

短期历史、长期摘要、知识库仍使用现有 PostgreSQL/Milvus，未采用同事的 SQLite。
联网为千问内置搜索，是否实际搜索由模型决定；日志记录上游返回的搜索次数（若存在）。
原音乐/天气本地动作与工具路由保留在级联线路，未迁移到此端到端线路。

本地无外部服务验证：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_hardware_qwen_realtime tests.test_hardware_audio tests.test_qwen_audio_voice
```

真机验证依次检查：启动 ready、识别文本、记忆/知识库命中、资料更新确认、MP3 首包和 done；
再测试智能体切换、联网问题、录音中取消/播放中取消，以及 route=cascade 回退。
已验证本机百炼握手/会话配置及实际 FFmpeg MP3 转码和解码；
完整语音生成、联网执行与真机播放仍需使用实际设备验证。
